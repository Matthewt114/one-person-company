# 资源清单

> 按**半衰期**排，不按"学习顺序"排。
> 半衰期长的先读、读透；半衰期短的用到再查，**不要背**。
> 一个学期最多两本书。读不完是正常的，写"读到第几章"也算完成。

---

## A 组 · 地基（半衰期 10 年以上）

| 资源 | 为什么读 | 状态 |
|---|---|---|
| 《深入理解计算机系统》CSAPP | 理解"程序为什么会错"的唯一入口。指针、内存、链接、并发 | |
| 《操作系统导论》OSTEP（[免费在线](https://pages.cs.wisc.edu/~remzi/OSTEP/)） | 比教材好读。"服务器一跑就崩""内存越用越多"全靠它 | |
| 《计算机网络：自顶向下方法》 | "连不上、超时、502、证书错误"是最高频的求助 | |
| 《修改代码的艺术》Working Effectively with Legacy Code | **接烂摊子的圣经**。怎么在没有测试的代码里加测试 | |
| 《重构》+《代码大全 2》 | 前者教安全地改结构，后者教写别人能读的代码。当字典查 | |
| 《单元测试的艺术》 | 第九法的工程实现。会写测试的人，报价天然高一档 | |

## B 组 · 排错专项（半衰期 5–8 年）

| 资源 | 为什么读 | 状态 |
|---|---|---|
| 《调试九法》142 页 | 先读这本。九条规则能直接当工作清单 | |
| [The Debugging Book](https://www.debuggingbook.org/)（免费） | 系统化调试教材。前三章读完就够开工 | |
| 《性能之巅》Brendan Gregg | 性能类单子的方法论：CPU/内存/IO/网络分层定位 | |
| [Julia Evans 的 zine](https://jvns.ca/zines/) | 用漫画讲 Linux 和调试，英文极浅，最适合大一的英文阅读入口 | |
| 《Debug Hacks》 | 工具流派（gdb/strace/ltrace）。用时再查 | |

## C 组 · AI 应用层（半衰期 6–18 个月，学模式不学 API）

| 资源 | 为什么读 | 状态 |
|---|---|---|
| [《Building Effective Agents》](https://www.anthropic.com/engineering/building-effective-agents) | agent 的工作流模式（路由、并行、编排、评估），比任何框架活得久 | |
| [Simon Willison 的博客](https://simonwillison.net/) | 这个领域最靠谱的独立信源，不卖课。每周扫一次标题 | |
| Cursor / Claude Code 官方文档 | **只查不背**。半年后一半会失效 | |

## D 组 · 商业与获客（半衰期 2–3 年）

| 资源 | 为什么读 | 状态 |
|---|---|---|
| 《The Mom Test》 | 怎么问客户，才知道他会不会真付钱。比任何接单话术有用十倍 | |
| 《小而美》Company of One | 一人公司的经营逻辑：为什么"不扩张"也是一种战略 | |
| 你所在城市的小商家 | 最好的行业理解来源，免费。观察他们怎么记账、哪里在浪费钱 | |

## E 组 · 免费的真实项目来源

| 来源 | 说明 |
|---|---|
| 学校实验室 / 老师的横向课题 | 真实需求、有预算、有人兜底。十个老师里有一个会给你活 |
| ACM 集训队 / 开源社团 / 创新创业中心 | 同伴是最稀缺的资源 |
| GitHub `good first issue`、[开源之夏 OSPP](https://summer-ospp.ac.cn/) | 范围明确的真实任务，做完就是公开战绩 |
| V2EX、电鸭、即刻 | 只读不发，每周 30 分钟，观察真实的人为什么问题付钱 |
