# git 笔记

## 2026-11-08 分支与冲突

---

## 一、分支是什么

到现在为止的历史，是一条直线：

```
3bafe28 → 9a3b423 → 66a1073 → ...
```

**分支 = 从直线上某一点分叉出去的一条新线。**

- 在岔路上随便改，**主线一点不受影响**
- 改好了 → 合回来
- 改砸了 → 把岔路删掉，主线什么都没发生

> 分支最重要的价值不是“并行开发”，是**“可以安全地放弃”**。

---

## 二、三个基本操作

```powershell
git branch                 # 看有哪些分支，星号是当前所在
git checkout -b 名字        # 新建并切过去
git merge 名字              # 把那条分支合到当前分支
git branch -d 名字          # 合完之后删掉
```

## 三、今天踩的坑：未提交的改动会跟着你走

在分支上改了一行，**没提交**就切回 main：

```
M       projects/scripts/csv_stat.py
Switched to branch 'main'
```

那个 `M` 说明**改动被带过来了**。因为 git 不知道这个改动属于哪条分支。

**提交之后就不会了。** 第二天同样的操作：

```
Switched to branch 'main'      ← 没有 M，改动留在分支上
```

| 改动状态 | 切分支时 |
|---|---|
| 已提交 | 留在原分支，不会跟过来 |
| 未提交 | 跟着你走 |

> **纪律：切分支之前先 `git status`。**

## 四、两种合并

### Fast-forward（快进）

主线在分叉期间**没有新提交**：

```
Updating 3bafe28..4b7b9cc
Fast-forward
```

git 直接把 main 的指针往前挪一格，**历史还是直线，看不出分叉**。

### 真正的合并（有 merge commit）

两边都有新提交：

```
*   b0378bd 合并 conflict-test：解决 README 冲突
|\
| * a0522e0 分支上：README 加一句
* | 3285a78 main 上：README 改同一行
|/
* 4b7b9cc （分叉之前的共同祖先）
```

`|\` 是分叉，`|/` 是汇合，`b0378bd` 是**合并提交**。

**只有这种情况才会产生冲突**——因为两边改了同一处，git 判断不了。

## 五、冲突长什么样

```
<<<<<<< HEAD
> 我是 Matthew Ma，大一，今天在练冲突解决。
=======
> 我是 Matthew Ma，大一，正在学 git 分支。
>>>>>>> conflict-test
```

| 符号 | 含义 |
|---|---|
| `<<<<<<< HEAD` | 当前分支（main）的版本，从这里开始 |
| `=======` | 分界 |
| `>>>>>>> conflict-test` | 要合进来的分支的版本，到这里结束 |

### 解决方式

1. 留当前分支的
2. 留要合进来的
3. **两个都要——自己写一句新的**（最常选的）

今天选了第 3 种：

```
> 我是 Matthew Ma，大一，正在学 git 分支和冲突解决。
```

> **冲突不是二选一的投票，是让你重新写一遍。**

### 解决步骤

```powershell
# 1. 打开文件，删掉三组标记，留下你要的内容
# 2. 告诉 git 已经解决
git add README.md
git status            # UU 变成 M
# 3. 完成合并
git commit -m "合并 xxx：解决冲突"
```

## 六、看历史的三条命令

```powershell
git log --oneline --graph --all     # 看分叉和汇合的形状
git show --stat HEAD                # 一次提交动了哪些文件
git diff HEAD~1                     # 和上一个版本比，差在哪
```

合并提交会多一行 **`Merge: 3285a78 a0522e0`** —— **两个父提交**，这是它和普通提交的本质区别。

`HEAD~1` = 当前提交的**第一个父亲**。

## 七、一条纪律

> **`git push` 之后，看一眼 `git status`。**

- `## main...origin/main` → 同步了
- `## main...origin/main [ahead 4]` → **还有 4 个没推上去**

今天就是因为没看，漏推了 4 个提交。
