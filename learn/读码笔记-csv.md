## 第二步：只精读一个类

`DictReader` 的 `__next__` 方法（第 112–132 行）是整个类的心脏。它的流程：

```
第一次调用 → 先读表头（存进 fieldnames）
之后每次   → 读一行 → 跳过空行 → 和表头配对成字典 → 返回
```

### 空行是在这里被跳过的（第 119–123 行）

```python
# unlike the basic reader, we prefer not to return blanks,
# because we will typically wind up with a dict full of None
# values
while row == []:
    row = next(self.reader)
```

`next(self.reader)` 每次取一行。**如果那行是空列表 `[]`，就再取一行，直到非空为止。**

注释也直接说了原因：空行配出来的字典全是 `None`，没有意义。

**注意"unlike the basic reader"**：基础的 `csv.reader` 是**会**返回空行的，只有 `DictReader` 主动跳过。同一个库，两种行为。

## 第三步：一个容易看漏的分支（第 127–131 行）

```python
if lf < lr:                        # 这一行比表头长
    d[self.restkey] = row[lf:]     # 多出来的塞进 restkey
elif lf > lr:                      # 这一行比表头短
    for key in self.fieldnames[lr:]:
        d[key] = self.restval      # 缺的列填 restval（默认 None）
```

`lf` = 表头列数，`lr` = 这一行的列数。

| 情况 | 含义 | 结果 |
|---|---|---|
| `lf == lr` | 列数正好对上 | 直接配对，空字段是 `''` |
| `lf > lr` | 这一行**比表头短** | 缺的列填 `None` |
| `lf < lr` | 这一行比表头长 | 多出的塞进 `restkey` |

---

## 最大的收获：`''` 和 `None` 是两回事

我原来的 CSV：

```
键盘,299,,缺货
```

切开是 `['键盘', '299', '', '缺货']` —— **4 个字段，和表头一样多**。

所以那个空的“数量”是 **`''`（这一格存在，但是空的）**，不是 `None`。

如果 CSV 少写一列：

```
商品,单价,数量
键盘,299
```

只有 2 个字段，表头 3 个 → **缺的“数量”才会是 `None`**。

> **`''` = 这格存在但空着；`None` = 这格根本没有。**
>
> 数据处理里这个区别很要命：前者是“客户填了空”，后者是“这份表没有这一列”。

## 这次学到的读码方法

1. **先列 `class` / `def`，看骨架**，别一上来读第一行
2. **一次只精读一个东西**，其余的先跳过
3. **注释常常直接告诉你"为什么"**，尤其是标准库
4. **带着自己的具体问题去读**——“为什么是 4 行不是 5 行”比“我想学习 csv 模块”有效得多
5. **读完能回答原来的问题**，才算真读懂
