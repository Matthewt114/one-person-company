## 这个仓库是什么

**不是教程，是一个人的训练记录。**

从大一开始，每周做一点，做出来的东西、踩过的坑、想明白的事，全部留在这里。
没有一个文件是抄的示例代码——`projects/` 下每个脚本都跑过、每个 bug 都修过。

如果你只想知道它有没有在动，看提交时间；
如果你想看一个人怎么从零开始，从 `learn/shell.md` 读起。

不同的人该从不同地方进，不用从头翻。

|---|---|---|
| **我自己**（每天开工） | [docs/进度.md](docs/进度.md) → 看"下次从这里继续" | 2 分钟 |
| **路过的开发者** | [learn/](learn/) 和 [postmortems/](postmortems/) | 10 分钟 |
| **找实习时的面试官** | [projects/](projects/) 和 [postmortems/001](postmortems/001-sorted-bug.md) | 5 分钟 |

> 三个入口都指向同一件事：**这个人真的动过手。**

## 三条自我约定

1. **大三之前不接陌生客户的付费单。** 一学期只做一次"零风险试水"（熟人、社团、老师、学校周边小店），目标是走完一次完整闭环，不是赚钱。
2. **大三之前不注册任何主体。** 个体户、一人公司、两人公司——等客户开始要发票时再说。
3. **不买任何"AI 副业课""接单训练营"。** 需要的资料全在这个仓库和公开文档里。

## 写东西的三条规矩

这是从别人仓库的结构里学来的，用在自己身上同样管用。

1. **失败当正文写，不塞进附录。** `docs/进度.md` 里那张坑表不是"常见问题"，是正文——写错的东西比写对的有用。
2. **观察和猜测分开。** 事实上发生了什么，写事实；我推断为什么，标一句"这是猜的"。猜错被后来的自己当成事实，是最贵的错误。
3. **具体压过形容词。** 写"改到第 30 张开始眼花"，不写"很麻烦"。数字和动作让人信，形容词不会。

## 为什么公开这个仓库

- 公开的计划比藏在硬盘里的计划多活三个月。
- 大三找实习时，这个仓库就是简历；比"熟练掌握 XX"有说服力。
- 陌生人能在 3 分钟内看懂你在干什么，是持续写作的唯一验收标准。
