# 大一上 · 八周执行清单（2026 秋季）

> 适用日期：**2026-11-02 ～ 2026-12-27**
> 每周投入：**5.5 小时**（项目 2 + 基础 2 + 写作 1 + 信息 0.5），分散到 3–4 个晚上
> 12/28 起进入期末复习，**计划归零**。挂科比进度落后严重得多。

**这份清单只做三件事**：把环境跑通、把方法论变成自己的、攒下第一批能给人看的东西。
不接单、不注册、不买课。

---

## 开始前：三条约定

1. **每周必须留一个"可验证产出"**，不是"看了/学了"。产出写不出来，说明这周白过。
2. **卡住超过 40 分钟就换路**，按下面第四节的四步走，不要硬扛。
3. **进度落后时，砍任务不砍产出**。八周计划里只有"产出"那一行是不可删的。

## 第 1 周 · 环境跑通

**目标**：让"写代码 → 存到云端"这条路第一次走通，以后再也不用折腾环境。

**任务**
- [ ] 装 Git for Windows：<https://git-scm.com/download/win>，装完在终端敲 `git --version` 能看到版本号
- [ ] 装 VS Code：<https://code.visualstudio.com/download>，装中文语言包
- [ ] 装 Python 3.12+：<https://www.python.org/downloads/>（安装时勾选 *Add Python to PATH*）
- [ ] 注册 GitHub，用户名用**真名拼音**（以后要给客户和面试官看）
- [ ] 配 SSH key：<https://docs.github.com/zh/authentication/connecting-to-github-with-ssh>
- [ ] 把本地这个仓库 push 上去
- [ ] 写 `hello.py`，`print("hello, world")`，提交

**看什么**
- GitHub 快速入门（中文）：<https://docs.github.com/zh/get-started/quickstart>
- Missing Semester 第 1 讲《课程概览 + Shell 入门》：<https://missing-semester-cn.github.io/2026/course-shell/>

**产出**：1 个公开仓库（`one-person-company`）+ 至少 5 次 commit

**验收**：不看任何教程，你能把一个本机文件夹变成 GitHub 上的仓库吗？

**5.5 小时怎么分**：装环境 2h / shell 1.5h / 第一个脚本 1h / 写 README 1h

## 第 2 周 · 命令行 + 九法前五法

**目标**：学会用命令行找东西，而不是用鼠标翻；知道"猜是排错最大的敌人"。

**任务**
- [ ] 看完 Missing Semester 第 1 讲，跟着把每条命令敲一遍
- [ ] 在自己的电脑上完成 20 个真实操作：列目录、找文件、看日志末尾、全文搜索、看文件大小
- [ ] 读《调试九法》第一至第五法（了解系统 / 让它失败 / 别猜去看 / 分而治之 / 一次只改一处）
- [ ] 建 `learn/shell.md`，每条命令一行，后面写"我用它干了什么"

**看什么**
- Shell 入门：<https://missing-semester-cn.github.io/2026/course-shell/>
- 命令行环境：<https://missing-semester-cn.github.io/2026/command-line-environment/>
- 《调试九法：软硬件错误的排查之道》David J. Agans，人民邮电出版社 2010，ISBN 9787115240576（142 页）

**产出**：`learn/shell.md` 至少 20 条命令 + 你自己的注释

**验收**：不用图形界面，只用命令行，找出你电脑里最大的 10 个文件吗？

## 第 3 周 · 九法后四法 + 写出自己的 SOP

**目标**：把书上的九条规则，变成一张你自己会照着做的清单。

**任务**
- [ ] 读完第六至第九法（保留审计线索 / 检查插头 / 找人看看 / 没有验证就不算修好）
- [ ] 填 `checklists/排错SOP.md`（仓库里已有空模板），**每条规则后面必须有一句你自己的话**
- [ ] 看 Missing Semester《Debugging and Profiling》，补上工具视角（什么时候用日志、什么时候用断点）
- [ ] 找一个真实的小问题（软件装不上、代码报错、网页打不开），**按 SOP 完整走一遍**，记录每一步

**看什么**
- Debugging and Profiling：<https://missing-semester-cn.github.io/2026/debugging-profiling/>
- The Debugging Book 前三章（免费）：<https://www.debuggingbook.org/>

**产出**：填好的 SOP + 1 份走查记录（`postmortems/` 下先建个草稿，第 7 周再正式写）

**验收**：不看书画出"从看到报错到定位根因"的流程图吗？

**注意**：第九法（A-B-A 验证）是这份 SOP 里最值钱的一条，也是未来你能报高价的理由。别跳。

## 第 4 周 · 手感 1：变量、分支、循环

**目标**：能写出 30 行以内、解决一个具体问题的小脚本。

**任务**
- [ ] 跟学校课程。**学校教什么就用什么**，不要另起一套——这里只补"动手量"
- [ ] 学校还没开编程课的话，二选一：
      CS50 Week 1（C，英文带字幕）<https://cs50.harvard.edu/x/weeks/1/>
      或 翁恺《C 语言程序设计》（浙大，中文）<https://www.icourse163.org/course/ZJU-9001>
- [ ] 写 3 个小脚本：
      ① 批量重命名一堆文件（比如把 `IMG_001.jpg` 改成 `2026-11-01-001.jpg`）
      ② 统计一段文字里每个字出现了多少次
      ③ 把一个文件夹里的图片按修改日期重命名
- [ ] 每个脚本配 3 行 README：干什么、怎么跑、踩了什么坑

**产出**：`projects/scripts/` 下 3 个项目，每个有 README

**验收**：不看教程写出"输入 10 个数，输出最大值、最小值、平均值"？

## 第 6 周 · 手感 3：文件、命令行参数、错误处理

**目标**：让脚本从"我能跑"变成"别人也能跑"。

**任务**
- [ ] 给最好的那个脚本加命令行参数（Python 用 `argparse`，C 用 `argc/argv`）
- [ ] 加错误处理：文件不存在时给一句人话，而不是甩一堆 traceback
- [ ] 打包成"能发给同学用"的形态：压缩包 + 使用说明（3 步以内）
- [ ] 真的发给一个同学，看他能不能自己跑起来

**产出**：1 个可交付的小工具 + 使用说明

**验收**：同学不问你，能自己跑起来吗？他卡在哪一步，就是你下个要修的地方。

## 第 7 周 · 第一次复盘

**目标**：完整走一遍"现象 → 根因 → 验证 → 预防"。

**任务**
- [ ] 选一个真实 bug：自己的、同学的，或 GitHub 上 small 项目的 open issue
- [ ] 按 `postmortems/000-template.md` 写，**必须有代码 diff 和验证过程**
- [ ] 标题里放具体报错关键词（"`ModuleNotFoundError` 明明装了却说找不到，原因是这个"）
- [ ] 先发一个平台（CSDN 或知乎），不追求流量，追求"写完整"

**看什么**
- 素材来源：GitHub `good first issue`、V2EX 问与答、知乎"AI 写的代码跑不起来"

**产出**：1 篇公开复盘（600–1200 字）

**验收**：一个完全不懂这个问题的人，看完能自己修吗？

**任务**

**产出**：1 份下学期计划 + 一个能给人看的 GitHub 主页

**验收**：陌生人能在 3 分钟内说出你在做什么、做到哪一步吗？

## 卡住了怎么办（四步，40 分钟内走完）

1. **自己查 20 分钟**：复制报错原文去搜，优先看官方文档和 Stack Overflow，不看 CSDN 转抄。
2. **问 AI，但要求它给提示不给答案**：明确说"只告诉我下一步查什么，不要贴完整代码"。直接抄答案，这周就白过了。
3. **问人**：同学、助教、课程群。问的时候带上：我想做什么、实际发生了什么、我试过什么。
4. **记进 `log/blocked.md`**：一句话写清卡在哪。每周日花 5 分钟翻一遍，你会发现一半的坑是同一个。

---

## 进度落后了怎么办

按这个顺序砍，砍到能完成为止：

1. 砍"看什么"里的第二条链接——书可以下周读，产出不能等。
2. 砍任务数量，但**保留产出那一行**：3 个脚本砍成 1 个，也要交 1 个。
3. 砍发文章的"发布"动作，先存草稿。
4. 实在不行，整周跳过，在 `log/` 里写一句"第 N 周跳过，原因是 X"。**记录跳过，比假装没发生有用。**

绝对不要为了补进度熬夜到凌晨——第二天的课和这周的产出，会一起崩。

**如果没有全部达成，也没关系**——只要最后一条能说出来，这八周就没白过。
