# 接单前自检（十二条）

> 打印出来贴墙上。每学期末对一次。
> **勾满之前，任何"要不要开始接单"的纠结都不必讨论。**

---

- [ ] **01 【交付】** 我能不看教程，从零部署一个带数据库的 Web 应用到公网。
- [ ] **02 【阅读】** 我能读懂 3000 行陌生代码的主流程，并画出它的数据流。
- [ ] **03 【定位】** 我能在完全不用 AI 的情况下，定位一个空指针或类型错误。
- [ ] **04 【测试】** 我写的代码有测试，并且我知道"先写一个失败的测试"是什么意思。
- [ ] **05 【版本】** 我能用 git 回滚、看 diff、独立解决一次合并冲突。
- [ ] **06 【报错】** 我能看懂一段报错栈，并说出最上面三层分别在说什么。
- [ ] **07 【方法】** 我有一份自己的排错 SOP，并且真的按它走过三次以上。
- [ ] **08 【作品】** 我有 3 篇公开复盘，每篇都有现象、根因、diff、验证。
- [ ] **09 【定价】** 我能说清这个 bug 会让客户损失多少钱或多少时间。
- [ ] **10 【合同】** 我有一份写清范围、预付款、验收标准的合同模板。
- [ ] **11 【退出】** 我知道这单如果修不好，我用什么方式、什么话术退出。
- [ ] **12 【边界】** 我能保证这单不影响我的绩点、考试周和睡眠。

---

## 勾满之后，再做这五件事

1. 写一份报价单（三档：诊断 / 修复 / 托管），中间那档是主力。
2. 写一份合同模板，至少包含：
   - 修复范围清单 + "不含清单外问题"
   - 既有代码质量免责（结构性缺陷可终止并按已完成工作量结算）
   - 保修期（例如"同一问题 30 天内免费重修"），**绝不写"永久免费维护"**
   - 源码与知识产权归属（默认不交源码，要交就加价）
   - 付款节点（预付 30%–50% 才开工）
3. 全程用微信或邮件沟通，重要变更让客户**文字确认**。
4. 第一单允许报价偏低，但**不允许免费**——免费的单子没有验收标准。
5. 交付时附一份验证报告（A-B-A 过程），这是专业度，也是保护自己的证据。

---

## 附：为什么是这些条

- 第 01–06 条是"能不能干"。
- 第 07–09 条是"会不会被白嫖"。
- 第 10–11 条是"出事怎么办"。
- 第 12 条最容易被忽略，也最致命：用健康和时间换来的第一桶金，往往不够支付后面的代价。
