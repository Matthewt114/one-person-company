# rename.py · 批量重命名图片

一句话：把一堆图片按**序号**或**修改日期**批量改名，改之前可以先演练。

---

## 解决什么问题

手机或相机导出的照片，名字大多是 `IMG_001.jpg`、`IMG_0002.jpg` 这种——顺序号毫无意义，混在一起根本分不清哪张是哪天的。

手动改的话：右键 → 重命名 → 输入 → 回车，一张一张来。**50 张要花十几分钟，而且改到第 30 张就开始眼花，容易漏、容易重名。**

这个脚本把这件事变成一条命令，50 张不到一秒。

---

## 怎么用

```powershell
# 按序号改名：photo-001.jpg、photo-002.jpg …
python rename.py "F:\照片" photo

# 按修改日期改名：2026-10-29-001.jpg …
python rename.py "F:\照片" --by-date

# 只演练，不真的改名（强烈建议先跑这个）
python rename.py "F:\照片" --by-date --dry-run
```

**推荐流程**：先带 `--dry-run` 跑一遍，看清每一行 `旧名 -> 新名` 都对，去掉 `--dry-run` 再真跑。

---

## 它做了哪些判断

- **只碰图片**：只处理 `.jpg` `.png` `.jpeg`，其他文件一概不动
- **目录不存在就退出**：打印「找不到文件夹：xxx」然后退出，不会乱跑
- **按修改时间排序后再编号**：保证序号和真实时间一致
- **幂等**：跑两遍结果一样，第二遍什么都不会变

---

## 踩过的坑

- **`sorted(os.listdir(...))` 排的是文件名，不是时间。** 一开始我用它排序，结果 8 月的文件拿到了 002、9 月的拿到 001。按日期命名必须指定 `key=lambda n: os.path.getmtime(...)`。
- **Windows 路径要加 `r`**：`r"F:\照片"`。不加的话 `\t` 会被当成制表符、`\n` 当成换行。
- **相对路径取决于“你在哪运行”**，不是“文件在哪”。所以脚本里用 `os.path.dirname(__file__)` 定位自己所在的目录。

---

## 已知问题

诚实写出来，免得别人踩：

- **不处理子目录**：只改 `folder` 这一层，里面的文件夹不管
- **只认三种格式**：`.jpg` `.png` `.jpeg`，其他格式跳过
- **目标文件名存在时会报错**：不会自动跳过或覆盖，会抛 `FileExistsError`
- **不记录改名历史**：改完就改完了，没法一键撤回。所以先用 `--dry-run`
